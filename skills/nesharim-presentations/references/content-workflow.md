# Content workflow

Proceed in quick mode when the user supplies only a topic. Ask only when missing information would materially change presentation type, core argument, source accuracy, or deliverables.

Identify one core insight, three to five supporting ideas, and a narrative arc: opening, tension, explanation, process, application, summary, closing.

## Slide rules

- One idea per slide; usually 10-15 slides.
- A title slide has one title and one short subtitle.
- Lists contain 3-6 meaningful items; grids 6-12 short labels; processes 2-5 steps.
- Avoid long paragraphs and generic filler.
- Preserve the user's terminology and factual claims; flag uncertainty rather than inventing support.

## Approval checkpoint

Before design, show the core insight and every slide's number, purpose, title, and content. Invite approval, edits, additions, removals, or reordering. Wait unless the user explicitly asks for uninterrupted execution or waives this checkpoint. Content approval authorizes visual production only; it does not authorize publishing or overwriting files.

After visual production, deliver an HTML proof and PDF proof for review. Apply requested changes and repeat as needed. Only the user's explicit final approval plus a request for a public link advances the deck to final PDF generation and publication.

## Finalized source and revisions

When the user supplies closed wording and waives content review, proceed directly to production. Preserve wording, slide order, and requested grouping; ask only about material omissions such as an ambiguous first slide/title. Do not turn slide-purpose notes into displayed text.

Treat slide numbers as belonging to the version the user is reviewing. After inserting/removing slides, identify requested changes by title as well as number and verify the new count. Distinguish the lecture opening, ordinary content (including the last content slide), and the separate contact closing.
